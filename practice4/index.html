    Практическое задание 4

    Чат на сокетах

    Требования:

    • Обязательно использовать библиотеку socket

    • Для многопользовательского чата обязательно использовать библиотеку threading

    • Организация возможности идентификации пользователей

    • Обеспечение возможности пользователю выйти из чата

    • выполнить с помощью протокола TCP

    Задание:

    Реализовать двухпользовательский или многопользовательский чат. 
Для максимального количества баллов реализуйте многопользовательский 
чат.

    Справка:

    Перед выполнением этого задания я почитал как подобные чаты организуются на реальных серверах. Оказалось, что это делается не с помощью потоков, а с помощью ассинхронности. Вместо создания новых потоков сервер очень быстро переключается меду сокетами и если сокет ничего не передает, то сервер им не занимается. Реализация чата с помощью библиотеки threading будет хорошо работать только в подобном задании, где нагрузка на сервер меньше 10 тысяч единовременных подключений.

    План выполнения:

    Сначала я напишу серверную часть кода, соответствующую требованиям. Затем напишу клиентскую часть, которая будет просить пользователя ввести его имя, затем я запущу клиентский код в нескольких экземплярах и проверяю как правляется сервер.

    Написание серверной части кода:

    Пишем стандартное начало: указываем хост и порт сервера и создаем 2 глобальных списка для клиентских сокетов и никнеймов.

    from pydoc import cli
import socket
import threading

HOST = ''
PORT = 9080

clients = []
nicknames = []

    Пишем функцию массовой рассылки. Она будет принимать на вход 2 аргумента. Первый - сообщение, которое надо передать пользователям, второй - порт клиентского сокета. Второй аргумент может быть пустым, если сообщение нужно отослать от имени сервера, а не пользователя вообще всем клиентам.

    def send_to_all(message, sender_socket = None):
    for client in clients:
        if client != sender_socket:
            try:
                client.send(message)
            except:
                pass # если сокет почему-то не работает

    Теперь пишем самую большую функцию for_one_client, которая будет инициализировать пользователей, сохранять их имена, их сокеты, принимать их сообщения, рассылать сообщения остальным и держать нас в курсе о статусе клиента: присоединился или покинул.

    Функция написана с помощью try, except и finally блоков. В блоке try сервер отпраляет клиенту требование авторизоваться, записывает его в свои списки, оповещает всех о присоединении нового пользователя. Затем читает все входящие сообщения от этого пользователя, превращает их сообщения в формат пользователь: сообщение и с помощью первого метода отсылает их остальным клиентам.

    В блоке except метод ловит любые виды ошибок, связанных с разрывом соединения с клиентом и дает нам возможность посмотреть логи.

    В блоке finally метод обрабатывает выход пользователя из чата стандартным способом, то есть в моем случае, если пользователь закрыл свой терминал и тем самым разорвал подключение. Метод удаляет клиента из своих списков, уведомляет всех пользователей о выходе и освобождает сокет.

    def for_one_client(client_socket):
    try:
        client_socket.send("Nickname_Request".encode('utf-8'))
        nickname = client_socket.recv(1024).decode('utf-8')
        nicknames.append(nickname)
        clients.append(client_socket)
        print(f"Пользователь сохранен как: {nickname}")
        send_to_all(f"Пользователь {nickname} присоединился к чату".encode('utf-8'), sender_socket=client_socket)

        while True:
            raw_message = client_socket.recv(1024)
            if not raw_message:
                break

            message = raw_message.decode('utf-8')
            user_message = f"{nickname}: {message}".encode('utf-8')
            send_to_all(user_message, sender_socket=client_socket)
    except Exception as e:
        print(f"Ошибка с клиентом {e}")

    finally:
        if client_socket in clients:
            index = clients.index(client_socket)
            clients.remove(client_socket)
            client_socket.close()
            nickname = nicknames[index]
            nicknames.remove(nickname)

            exit_massage = f"Пользователь {nickname} покинул чат".encode('utf-8')
            print(exit_massage.decode('utf-8'))
            send_to_all(exit_massage)

    Ну и метод запуска главного потока сервера start_server(). В этом блоке я поймал больше всего ошибок при тестировании кода. Главный принцип написания главного потока - он должен только раздавать каждому клиентскому сокету свой поток. Нельзя давать ему никаких доп задач, например, я сначала пытался сделать авторизацию пользователя именно здесь, что в итоге просто морозило мой главный поток и ни 1 другой клиент не мог ничего сделать, пока первый клиент вводил имя.

    Поэтому этот метод просто создает сокет сервера, который слушает все подключения. Как только серверный сокет принял подключение, он сразу передает клиентский сокет потоку и освобождается для принятия нового соединения.

    def start_server():
    server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1) # для мгновенного освобождения порта сервера
    server.bind((HOST, PORT))
    server.listen()
    print("Сервер запущен и ждет подключений")

    while True:
        client_socket, client_address = server.accept()
        print(f"Новое соединение с адресом: {str(client_address)}")

        thread = threading.Thread(target=for_one_client, args = (client_socket,))
        thread.start()


if __name__ == "__main__":
    start_server()

    На этом написание кода для сервера завершено.

    Написание кода клиента:

    Тут как обычно все намного проще.

    Создаем сокет, пытаемся подключиться к серверу, если не удалось - сообщаем об этом и завершаем выполнение.

    import socket
import threading
import sys
import time

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

try:
    client.connect(('127.0.0.1', 9080))
except ConnectionRefusedError:
    print("Не удалось соединиться с сервером")
    sys.exit()

    Далее вводим глобальную переменную authentificated и устанавливаем её занчение в False. Она будет нужна далее для того, чтобы обеспечить возможность писать в чате только авторизованым пользователям.

    authentificated = False

    Далее пишем метод recive_massages, через который клиент сможет авторизоваться на сервере, получив от него соотвествующее требование, и просто сможет видеть, полученные от сервера сообщения. Тут простая логика: если сервер отправил запрос на авторизацию, клиенту будет предложено ввести свой ник, который отправится на сервер и изменит значение переменной authentificated и даст возмоность самому писать сообщения, если же сервер просто прислал соощение, то пользователь его увидит у себя.

    def recive_messages():
    global authentificated
    while True:
        try:
            message = client.recv(1024).decode('utf-8')
            if message == 'Nickname_Request':
                nickname = input('Сервер запрашивает имя пользователя: ')
                client.send(nickname.encode('utf-8'))
                authentificated = True
                print("Вы успешно авторизовались, для выхода из чата введите esc")

            else:
                print(message)
        except:
            print("Соединение с сервером потеряно")
            client.close()
            break

    Далее обратный метод для отправки сообщений send_message(). Метод крутится в бесконечном цикле с небольшим интервалом между итерациями, пока пользователь не введет свое имя и флаг authentificated не примет значение True. После этого пользователю будет предложено ввести текст, который далее будет отправлен на сервер или же повлечет аварийное закрытие сессии.

    def send_messages():
    while True:
        if not authentificated:
            time.sleep(0.1)
            continue

        raw_message = input("Введите текст: ")
        if raw_message.lower() == 'esc':
            client.close()
            sys.exit()

        try:
            client.sendall(raw_message.encode('utf-8'))
        except:
            break

    Ну и в самом конце создаем потоки, чтобы методы работали параллельно и не блокировали друг друга. (Тупо если сообщение с сервера не приходит, если пользователь параллельно пишет свое в input) При этом процесс получения сообщений делаем фоновым, чтобы если пользватель закрыл сессию, клиентский код не дожидался пока сервер отправит все сообщения, что у него есть.

    threading.Thread(target=recive_messages, daemon = True).start() # фоновый процесс
threading.Thread(target=send_messages).start()
